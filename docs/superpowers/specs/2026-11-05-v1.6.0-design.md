# DFAST 1.6.0: Prodigal, Diced and no bundled executables

**Date:** 2026-11-05
**Branch:** release/1.6.0 (has the GHOSTX one-process change, 1568ced, on top of 1.5.2); master (1.5.5) must be merged into it first.

## Intent

Ver 1.5 removed the bundled executables except MGA and CRT, keeping results compatible. Ver 1.6 finishes the
switch (see the Roadmap in `docs/history.txt`, Ver 1.5.0): CDS prediction moves from the bundled MGA to Prodigal,
CRISPR detection moves from the bundled CRT (Java) to Diced, and `--use_rnammer` is removed. Then DFAST contains
no bundled executables and no Java, and can run on linux-aarch64 and osx-arm64. CDS predictions change with
Prodigal; that is accepted for 1.6.

What the user cares about most:
1. A gene whose start codon is exactly at the beginning of a sequence (or, on the minus strand, at its end) must
   still be annotated as a complete CDS, in draft genomes as well as complete ones. MGA sometimes missed such genes
   or called them partial; the existing fix in `FeatureUtil.fix_partial_CDS` (feature_util.py) must keep working
   with Prodigal.
2. Annotation with translation tables other than 11 must work. The tables in scope are 4 (Mycoplasma) and 25
   (SR1/Gracilibacteria).

## Goals

- **Prodigal is the default CDS predictor.** `--use_mga` selects MGA instead.
  - `--use_prodigal` becomes a no-op kept for compatibility: it logs a warning that Prodigal is now the default.
  - `--metagenome` runs Prodigal with `-p meta` (MGA with `-m` when `--use_mga`), as now.
  - Prodigal is run as the `prodigal` executable, as in the existing `dfc/tools/prodigal.py` (not pyrodigal).
  - Some builds of Prodigal 2.6.3 write a broken GFF attribute column (no `ID`, `partial`, `start_type`, ...):
    the Ubuntu 24.04 apt package `/usr/bin/prodigal` (2.6.3-6) does; Bioconda and Debian trixie (Docker) builds do
    not. DFAST must detect this (no `partial=` in the attributes) and stop with an error that names the cause,
    instead of silently treating every gene as complete.
  - Prodigal's normal (single) mode needs at least 20,000 bp of sequence to train. When the input is shorter,
    DFAST switches to `-p meta` automatically and logs it (table 11 only, see below).
  - Prodigal's meta mode ignores `-g` (verified: `-p meta -g 25` and `-g 11` give identical proteins) and its models
    cover only table 11 and some table-4 genomes. Therefore, with `--gcode` other than 11 (user's decision), Prodigal
    always runs in single mode: `--metagenome` together with `--gcode` other than 11, and input shorter than 20 kb
    with `--gcode` other than 11, stop with an error that explains why.
- **Genes at the sequence ends.** `fix_partial_CDS` must convert a Prodigal edge gene (partial_flag "10" on the plus
  strand starting at 1, "01" on the minus strand ending at the sequence end) to a complete CDS under its existing
  conditions. Verified on 1.5.5 with `--use_prodigal`: 19 of 20 test genes fixed (dev/v160/edge_start/README_ja.md).
  The conditions (length >= 500 bp, a database hit, ATG/GTG/TTG at the edge) stay as they are.
- **Translation tables 4 and 25.** `--gcode` accepts 4, 11 and 25 (and passes any other NCBI table through with a
  warning, as now).
  - The same table reaches every place that uses it: Prodigal `-g`, Aragorn `-gc<n>`, the translation in
    `StructuralAnnotation.setFeatures`, PseudoGeneDetection (`lastal -G`), NuclMapping, and the `/transl_table`
    qualifier.
  - Start codons come from Biopython's table (`CodonTable.unambiguous_dna_by_id[n].start_codons`), replacing the
    hard-coded lists for tables 4 and 11 in `_get_translation`. For table 25 the start codons are ATG, GTG and TTG.
  - `--use_mga` supports table 11 only: MGA from Bioconda has no table-4 variant (the bundled `mga_4` goes away).
    `--use_mga` with `--gcode` other than 11 stops with an error that suggests the default (Prodigal).
- **Diced replaces CRT** for CRISPR detection, with the CRT parameters: min repeat length 19, max repeat length 38,
  min spacer length 19, max spacer length 48 (CRT's search window 8 equals the MinCED/Diced default).
  - Diced >= 0.1.4 (the `diced.scan` keyword arguments come from the user's merged PR althonos/diced#2).
  - Diced handles multi-FASTA, so the concatenation of contigs with 200 Ns in `dfc/tools/CRT.py` is not needed.
  - The output keeps the CRT features: the CRISPR range and the most frequent repeat sequence as `rpt_unit_seq`
    (counted from the repeats, not taken from a consensus), so results stay comparable.
  - CRT is removed completely (no option to keep it), with `bin/common/CRT*` and the Java dependency.
  - Known Diced issue: iterating `crispr.spacers` to the end panics in Rust (lib.rs index out of bounds) instead of
    raising IndexError; use `len()` and indexing.
- **Remove `--use_rnammer`**, the RNAmmer tool and its config entries.
- **Remove `bin/`** (MGA, mga_4, CRT). MGA is used from PATH (Bioconda `metagene_annotator`, linux-64 only).
- **Docker image**: Prodigal (apt, Debian build is correct), Diced (pip), and MGA (from the Bioconda
  `metagene_annotator` package, linux-64). Java (`default-jre`) is removed. The image stays pinned to linux/amd64.
- Include the GHOSTX one-process change already on release/1.6.0.
- Docs: README (options, dependencies), `docs/history.txt` 1.6.0 entry (including how CDS predictions change and the
  Roadmap update), CLAUDE.md (no bundled binaries; MGA/CRT mentions), web configs
  `example/dfc_config/dfast_web_config*.py` in sync with the default config.
- **Web-service configs switch to Prodigal and Diced** like the default config (user's decision). Deploying 1.6.0 to
  the web service therefore needs `prodigal` and `diced>=0.1.4` (PyPI) in the production environment first; the
  deploy itself is not part of this work.

## Non-goals

- pyrodigal, or any new gene caller other than Prodigal.
- Changing the rules of `fix_partial_CDS` (it is only verified with Prodigal).
- Handling genes that span the origin of a circular sequence.
- Translation tables other than 4, 11 and 25 beyond passing them through.
- The Bioconda recipe update: the user will update it at the 1.6.0 release together with the new dependencies
  (prodigal, diced, integron_finder, defense-finder). Bioconda has diced 0.1.3 only; 0.1.4 is on PyPI.
- `--modules` (a separate later change).

## Anti-goals

- Silently wrong CDS calls: a Prodigal build that loses the partial flags must not be accepted.
- A Java or bundled-binary dependency left in the default workflow.

## Validation (agreed)

- The 5 genomes used for the earlier validations (dev/new_tools/genomes: E. coli MG1655, A. baumannii AYE,
  V. cholerae N16961 chr2, pOXA-48, DFAST sample), `--amr --mge`, Prodigal (default) vs `--use_mga`:
  exact CDS matches to RefSeq for MG1655 (as in dev/nucl_mapping/compare_refseq.py), ddbj-validator with no new
  errors, no unexpected WARNING/ERROR in the logs.
  - Designer's call (not confirmed by the user): the RefSeq comparison is reported, not a pass bar, since
    CDS predictions are allowed to change; a large drop against `--use_mga` is reported to the user.
  - Designer's call: expected warnings are not failures, e.g. the existing "Fixed partial CDS" / "annotated as
    misc_feature" warnings of `fix_partial_CDS` (Prodigal marks edge genes partial more often) and the new
    `--use_prodigal` no-op warning. Their log levels are not changed.
- The edge-start test (dev/v160/edge_start: 20 contigs) with 1.6.0: at least the 19 complete CDSs seen with
  Prodigal on 1.5.5.
- `--gcode 25` with `--metagenome` and with input under 20 kb stops with the error.
- One genome each with `--gcode 4` (Mycoplasma genitalium G37) and `--gcode 25` (an SR1/Gracilibacteria genome,
  accession chosen by the builder): runs without errors, `/transl_table` and translations use the table, validator
  shows no translation errors.
- CRISPR: Diced with the CRT parameters on the 81 genomes of dev/update_crt matches the earlier comparison (115 of
  120 identical to CRT).
- `python -m pytest -q tests` passes (with the fake mefinder on PATH).
