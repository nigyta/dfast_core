# `--modules` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Select the accessory annotations with `--modules` (amr, vf, plasmid, mge, integron, defense, all); `--amr`/`--mge` stop with an error that points to `--modules`.

**Architecture:** A module table in `dfc/utils/config_util.py` maps each module name to the config entries it enables (they already exist, disabled, in the default and web configs). `dfast` calls one helper. The downloader gets the same names. No new config entries.

**Tech Stack:** Python 3.10+, argparse, pytest.

**Spec:** agreed in chat on 2026-11-05 (no design document): see "Agreed behaviour" below.

## Agreed behaviour (user decisions, binding)

- `--modules NAME [NAME ...]` with NAME in `amr` (CARD, NuclMapping), `vf` (VFDB, NuclMapping), `plasmid` (PlasmidFinder), `mge` (MobileElementFinder), `integron` (IntegronFinder), `defense` (DefenseFinder + AntiDefenseFinder), or `all` (all six, including defense: the DefenseFinder developers allow its use as long as DFAST does not redistribute the models). Unknown names are an error (argparse choices). No `--modules`: no accessory annotation (as now).
- Missing tool or data: with `all`, that module is skipped with a WARNING; a module named explicitly stops DFAST with an ERROR (exit 1) that says what is missing and how to install it. A module named explicitly together with `all` counts as explicit.
- `--amr` and `--mge` stay as options for now, but using either stops DFAST with an error: "--amr was removed in Ver 1.6. Use --modules amr vf plasmid defense (or --modules all)." and "--mge was removed in Ver 1.6. Use --modules mge integron (or --modules all)."
- A CARD/VFDB `NuclSearch` entry enabled in a config is used instead of the NuclMapping of that database (same rule as the current `enable_amr`).
- `dfast_file_downloader.py --modules NAME [NAME ...]` downloads what the modules need: amr → CARD and vf → VFDB (as `scripts/reference_util_for_nucl.py --card` / `--vfdb`, into the same DB root), plasmid → as `--plasmidfinder`, mge → as `--mefinder`, defense → as `--defensefinder`, integron → nothing to download (log that). `all` → all of them.
- Docs: README (options, the AMR/MGE sections, examples), `docs/history.txt` (top entry `Ver 1.6.0 (unreleased)`), CLAUDE.md where it names `enable_amr`/`enable_mge`.
